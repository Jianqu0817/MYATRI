# 记忆与检索修复接续复核

2026-10-20。接续余额中断前已存在的实现；本次新增生产修改仅在 `src/myatri/memory/index.py`，其余记忆/检索修补按现状独立复核。未改 app、公共契约、认知、会话或依赖。

## 已核验行为

- 请求快照水位与安装世代不相等时，跳过该世代的向量、主题和相似图；直接从请求快照的语义关系记录恢复关系。较新关系修订、未来主题摘要不会影响过去快照。FTS 的读事务同时检查投影水位，不将新语料的排名投影用于过去快照。
- 单次 recall 捕获并沿用同一世代，避免向量查询期间并发安装造成主题/图混代。
- 构建保存档案序号，并在档案共享写锁内检查 current 水位。慢旧构建不能倒退 current；共享实例和独立实例均覆盖。旧版缺少序号的世代/指针仍可载入，显式 rollback 可恢复旧世代。
- 索引成员保持最新 revision；关系证据检查使用快照内所有不可变 revision。临时状态从 thought@1 更新为 @2 后，以 @1 为证据的合法关系仍可重建，且当前状态视角只索引 @2。
- 查询原文中的非法日历日期保留为可搜索文本，并附带限制说明；当前回复和下一次回复均可继续。
- 档案读取、本地 TF-IDF 拟合/变换、图与聚类、序列化/发布分阶段进入线程。阻塞聚类的测试期间前台真实 respond 能完成；外部异步 embedding provider 的 embed 仍在调用者事件循环和线程运行。

## 接续中发现并修正的新竞争条件

`_prepare_rebuild` 原先先读取档案，之后才捕获已安装世代。若旧读取固定在水位 N，新构建在间隙发布水位 N+1 的模型主题摘要，旧构建便会把未来主题名称/摘要作为 previous_themes 携入 N。current 单调发布能够拒绝指针倒退，却仍会把污染的旧世代保存为可显式 load/rollback 的文件。

本次把世代/缓存捕获移动到档案读取之前，让主题继承至多来自读取之前已有的档案；旧构建文件本身也与其水位一致。新增正常收集的并发回归：阻塞旧快照读取，发布未来主题摘要及新索引，再释放旧构建，检查 current 保持新世代，同时全部旧水位保存文件都不含未来主题文字。

额外使用只修改进程中方法、不触碰源码的 mutation probe 恢复旧顺序：新回归稳定以“旧世代含未来摘要”断言失败，探针将预期失败验证为成功退出。脚本：`reports/fix_memory_mutation_probe_2026-10-20.py`。该预期失败不计入正常通过数。

## 实际测试

```powershell
.venv/Scripts/python.exe -m pytest tests/test_memory.py tests/test_memory_consistency.py tests/test_retrieval.py tests/test_neural.py tests/audit_memory_consistency.py -q --tb=short --basetemp=reports/fix_memory_final_tmp --junitxml=reports/fix_memory_final_2026-10-20.xml
```

结果：**35 passed，10.60 秒**。无 xfail、无 skip。旧 audit 入口现为正常回归的兼容导入，因此这 35 个收集结果包含 3 个与默认 test 文件重复执行的历史审计用例，不应称为 35 个独立新场景。对应默认记忆/检索/神经文件是 **32 个收集用例**。接续修改前这四个文件的基线为 31 passed，15.19 秒；新增并发用例后多 1 个。

所有写入档案都是 pytest basetemp 下的合成隔离档案。神经回归在本机可用，读取现有本地 BGE 模型文件验证离线推理与重启，未下载、未调用网络 API、未读取密钥或真实用户运行档案，未改实际 var 数据。

## 保留限制

- 仍为全量重建基线；线程隔离改善前台调度，不减少全量图/聚类的总计算量，也不证明任意规模下的硬实时响应。
- 过去快照无法匹配当前索引时使用来源正确的词面/语义边回退，不宣称具有过去神经向量世代同等召回质量。
- 图关系的 valid_from/valid_to/status 全生命周期语义未在本次扩大设计；这里检查的是档案提交快照与确切 revision 的可见性。
- 当前结构回归验证持久性、时间一致性及可恢复性，不能据此宣称达到最像人类的长期行为效果；该目标仍需要连续、多场景的独立评估。
