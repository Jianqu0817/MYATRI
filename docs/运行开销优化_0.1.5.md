# 运行开销优化与消息时间（0.1.5）

2026-10-21后续配置更新（0.1.6）：用户将10/30调整为30/50。当前完整诊断与投影约30轮（投影60次提交），记忆/情绪/状态50轮，反思/关联/主题/归因约150轮，人格审阅约300轮；日额度50M，单次窗口1M和650k压缩阈值不变。原话即时保存、压缩前补齐依赖、消息发送时间和缓存机制均保留。以下频率表与性能/测试数据记录0.1.5优化基线，新配置重启后生效。

2026-10-21：按用户授权减少本地记录和后台 API 频次。适用于默认配置与 Windows 一键启动使用的 live.local.toml，重启后生效。

## 普通对话的频率

| 操作 | 新频率 | 说明 |
|---|---|---|
| 用户原话、助手回复 | 每条即时保存 | 原记录和发送时间进入不可变档案；出错、关闭或重启不依赖内存补写 |
| 完整上下文诊断、状态选取追踪 | 每10个完成轮次检查点 | 有候选才生成选取追踪；其余轮仍选取状态，但不重复生成完整诊断档案 |
| 已完成工具协议 | 每轮只留简要状态 | 每10轮保留完整请求诊断；尚未完成的工具往返仍立即完整保存，支持恢复 |
| SQLite/FTS投影 | 约10轮，或20次档案提交 | 改为追加缺失记录；维护完成、检查及正常退出时也刷新。滞后时检索使用权威档案回退 |
| 记忆提取、事件情绪评价、临时状态整理 | 每30轮 | 原话仍即时可见；长期整理有延迟，情绪投影仍可在本地随时间衰减 |
| 反思、关联/主题整理、反馈归因 | 每3个维护批次，约90轮 | 延后材料保留在持久待办中，不只看最后一批 |
| 人格变化审阅 | 每6个维护批次，约180轮 | 有合适材料才审阅；证据不足或预算不足可defer，不保证产生变化 |
| 后台空队列轮询 | 每5秒 | 不影响前台直接发起的回复 |
| 自动上下文压缩 | 650k软阈值 | 单次窗口仍1M；压缩前补齐积压的记忆、情绪、反思与人格审阅依赖 |

一个轮次指一次已保存的用户消息与其助手回答。批次边界因压缩前强制整理、旧待办恢复而可能略有偏移。已有排队任务不会通过删库来消除；新策略接续保存的检查点。

只对可重建投影和诊断降频，没有把未保存原话积攒10轮。正常退出不强制发送后台 API 来整理不足30轮的消息；下次继续累计。工具请求进行中仍立即保存协议边界，预算用量仍即时记账。

## 每条消息的时间

原话 `created_at` 继续保存UTC时间。每轮给模型的普通历史消息增加 `消息发送时间`，转换为Asia/Shanghai、带`+08:00`；继承历史数据保留UTC时间并提供当地时间。本轮另带服务端当前时间，终端助手回复也显示时间。

记忆提取窗口、反思材料、压缩原文窗口与新摘要摘录包含原记录时间。引用跨度仍只对照未改写的原话，不把时间前缀写入原文。发送时间是服务器接收/生成记录时间，不代表用户在消息里叙述的事件发生时间；未知事件日期仍未知。

## 本地性能改动

1. 已校验文件按大小、修改时间和创建/变更时间缓存；重复读取复用解析结果。新增提交或文件元数据变化会使对应读取失效。返回的模型深拷贝，调用者修改嵌套字段不会污染缓存。
2. 启动和doctor仍检查档案；doctor强制重新读取并校验全部已提交字节，不仅信任文件元数据。原始记录、来源和版本仍是权威。
3. 维护最多4份读取快照缓存；投影从当前水位增量追加，不在每次新原话后删除并重写整张表。损坏/缺失投影仍可从档案重建。
4. 完整协议和token估计锚点按10轮保存检查点，减少把整段历史反复写入runtime.sqlite3。每轮锚点仍在内存中用实际API usage校准，正常退出补存。
5. 普通30轮整理只在末尾更新索引；90轮深整理需要关联查询时才额外提前更新一次。

这次没有增加新模型、新外部服务或新依赖，也没有改成每轮反思。小温暖完整角色卡和首尾身份锚点仍在每次请求中；ATRI继承记忆仍是带来源的数据。
