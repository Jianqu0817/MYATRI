## 2. 两层互联的记忆入口

第一层是稳定入口：人物、项目、地点和技能。它回答“这是谁/是什么，我们有哪些相关经历”。第二层是动态主题：由材料逐渐形成，回答“这些经历有哪些共同模式”。二者互联，不能互相替代。

- 第一次有来源地提到新人，可立即建立暂定人物入口，不等待多次相似事件。
- 明确提出“学习Python文件处理”，可建立待学习入口；提出要求只证明存在学习目标。
- 一个事件可关联多个人物、多个技能和多个主题，不为每个入口复制原文。
- 一个主题可以跨越多个人物或技能；主题分裂/合并不能改变实体或技能的稳定身份。
- 索引只改变组织与可发现性，不能增加独立外部证据数量，更不能自动改变人格。

这里的“入口”是可持久化、可查询的逻辑索引，不预设每个人物必须拥有单独向量数据库或物理文件夹。

## 3. 动态实体设计（待实现）

### 3.1 人物示例

首次出现“今天认识了小林”时，保存原文和事件，再提出暂定人物入口。后续“小林帮我排查程序”“和小林散步”都可关联同一入口，即使两件事在语义聚类中属于不同主题。

“林同学”“小林”“他”可能指同一人，也可能不是。抽取模型只能提出候选；材料不足先保留独立或pending，不把同名、同职业或向量相似当作身份证明。提到小说角色或假设人物时保留reality_scope，不混为真实交往。

### 3.2 拟议字段与关联

| 对象 | 拟议字段 | 约束 |
|---|---|---|
| Entity | entity_id、revision、kind、display_name、aliases、status、source_refs | kind先支持person/project/place；每条别名也保留依据 |
| EntityLink | entity_ref、record_ref、relation、evidence_refs、status、valid_from/to | 引用确切revision；mentions/participates_in/about等关系语义明确 |
| EntityResolution | 候选ID、merge/split/keep_pending、原因、来源、被替代版本 | 合并/拆分不删除原始事件，保持历史可读与可回退 |
| EntitySummary | entity_ref、材料水位、摘要、反例、未知项、source_refs | 摘要是派生解释；事件修订或材料变化后标记待更新 |

以上均为设计字段。当前不存在对应生产record_kind，实施时先由主Agent统一修改契约。保留旧participants字符串兼容读取，再增加明确实体关联，不直接改写历史原文。

### 3.3 提案和更新流程

1. 从已保存消息/事件读取快照，LLM提取候选及逐字依据。
2. 用姓名/别名、语义、共同事件和时间上下文寻找已有入口；候选相似不等于同一实体。
3. 提出新建、关联、保留歧义或合并建议，交统一提交器检查来源、read_versions、隔离与幂等性。
4. 提交后更新检索投影；索引落后时按档案关联回退或明确报告水位。
5. 新材料使摘要过时时更新派生摘要；不把此前摘要再算作新外部经历。

## 4. 技能学习记忆设计（待实现）

### 4.1 学习入口保存什么

| 内容 | 拟议记录 | 为什么要分开 |
|---|---|---|
| 学习目标 | Skill：稳定ID、名称/别名、目标、范围、状态、来源 | 想学习不等于已经具备能力 |
| 材料与理解 | 来源片段、概念、解释、问题及关联 | 用户讲解、模型推断和实际结果不能混成事实 |
| 可复用方法 | Procedure版本：步骤、前置条件、适用场景、限制、来源 | 可修改并追溯，不能用新总结覆盖旧失败依据 |
| 实践尝试 | 关联BehaviorAttempt、任务输入、步骤版本、行动/执行记录 | 需新增工具结果契约/适配；没有执行来源，不能声称已做过 |
| 反馈与验证 | 结果来源、判断方法、通过/失败/未知、适用范围、错误 | 一次通过不证明普遍掌握 |
| 检索入口 | 相关事件、实体、主题和步骤引用 | 后续任务可找回经验并产生新的结果记录 |

学习状态可先用planned/learning/paused/archived表示流程；验证状态另记untested/passed/failed/unknown及其场景，不用单一分数或次数自动授予“精通”。具体枚举实施前再锁定。只有任务要求和真实可用工具匹配时才执行，记忆模块本身不提供通用执行器。

### 4.2 Python文件处理示例

“学习Python文件处理” → 建立planned入口 → 阅读材料并记录编码疑问 → 提出“读取UTF-8文件”的步骤草案 → 在本地允许的测试环境实际练习 → 保存成功/报错及输出 → 修订步骤并限制适用条件 → 后续处理日志时检索该入口，完成后追加反馈。

若只有讲解与总结，没有执行证据，保留learning/untested。给Agent发一条学习指令不会训练模型权重，也不会自动联网、安装软件或获得账户权限。

### 4.3 内容判断与程序职责

LLM负责提出技能归属、总结步骤、解释错误和建议修订；程序负责来源片段校验、版本/CAS、权限、任务执行结果采集及验证记录。模型自评“我学会了”不能替代测试结果。多个步骤版本可以共存，失败、反例和不确定信息应可检索。

现有record_attempt_feedback仅接受持久assistant原始消息作为已表达/尝试的action_refs，反馈要求reported/observed事件，并要求有效临时意图。它不能直接接收Python退出码或测试产物作为工具行动。DMI-04必须新增/适配有类型的执行结果与技能目标/临时意图关联，不能把程序输出伪装为assistant消息来绕过校验。

## 5. Embedding的当前实现

### 5.1 后端与输入

| 项目 | TF-IDF默认 | BGE可选 |
|---|---|---|
| 实现 | sklearn字符1–4 gram，sublinear_tf | Xenova/bge-small-zh-v1.5，ONNX量化INT8/CPU |
| 版本 | 拟合语料与view哈希生成revision | 75c43b069aac4d136ba6bc1122f995fedcfd2781 |
| 向量 | 维度随词表变化，L2归一化 | CLS池化、512维、L2归一化 |
| 输入边界 | 词面匹配能力，重新fit形成新空间 | tokenizer最多512 tokens；当前超长直接截断 |
| 运行 | 无模型下载 | 已有本地模型；新环境需显式下载，普通聊天不自动下载 |

DeepSeek目前提供对话和认知API，当前Embedding不是DeepSeek API。BGE下载/测试成功不代表所有root已迁移；Application按配置或运行库保存的设置选择provider。公开defaults.toml明确backend=tfidf。

### 5.2 多视角

event视角编码事件文本及部分原文、解释、反思、人格变化和会话摘要；feeling编码记录已有的感受/期待；theme编码已保存主题正文/描述；temporary_state编码临时状态文本。不是所有记录都有四份向量。缺失感受就跳过；感受解释只有单事件来源时才可直接anchor回事件参与相似图。

视角各自检索，不把不同space的向量直接拼接比较。“512维”不表示每一维对应一个人物或技能。未来Entity/Skill/Procedure描述向量属于新扩展，不能列为当前已有视角。

### 5.3 检索与图

当前NumPy精确余弦搜索；相似图默认k=5、threshold=0.08，事件/感受权重0.7/0.3，缺失视角重归一化并限制最终度数。聚类仅以事件为节点，默认seed17、递归resolution=[0.5,1.25]，使用真实Leiden。相似度不是支持/矛盾/掌握概率，语义关系单独保存。

回忆还结合中文trigram FTS、档案词面、人物/时间过滤、主题成员和类型化图扩展，RRF按名次融合。当前并非已实现的实体消歧、LLM全候选重排或ANN。已有小样本评估显示图/主题/多视角可能无提升或降低排序，不能把复杂度当作效果。

### 5.4 存储、更新与待改进

向量行绑定record_id/revision及模型/空间元信息。缓存键使用text_hash、view、model/revision、dimension、normalization与space_id，不含record_id/revision；相同文字可复用计算，但每条记录的来源与版本仍独立保存。不同空间即使等维也不能混查。索引generation保存完整状态和水位，可重启加载；旧BGE空间需要匹配provider。原文和版本档案权威，向量可重建。

当前update仍全量重建向量索引、相似图与群落，不具备局部增量保证。BGE每份长文本只保留截断输入的表示，原文完整保留不等于其全部内容参与语义检索。未来分块必须绑定原记录revision与offset，并保存覆盖率/截断信息、同源去重和聚合规则。M01/M02未修，不能宣称所有快照/并发索引检查已通过。

源码核对入口：[embeddings.py](../src/myatri/memory/embeddings.py)、[local_onnx.py](../src/myatri/providers/local_onnx.py)、[index.py](../src/myatri/memory/index.py)、[themes.py](../src/myatri/memory/themes.py)、[检索](../src/myatri/retrieval/service.py)。
