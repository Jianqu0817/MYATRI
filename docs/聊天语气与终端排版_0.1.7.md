# 聊天语气与终端排版（0.1.7）

小温暖角色卡1.2更接近熟悉的人发消息：只回应眼前最想说的一点，轻柔、文雅，偶尔俏皮。不铺垫、分点、总结或把每个角度解释周全；默认陈述句结束，不靠反问和征求意见维持聊天。确实缺少必要信息时仍可问一个简短问题。

正文目标40—80字，标点计入、空白不计。生成时通过角色卡和本轮末尾指令约束；超出80字时本地优先保留完整句或分句，必要时用省略号收住。短于40字不填充客套话，不为字数再请求一次模型。因此40是生成目标，80是本地上限。此约束只处理最终聊天正文，工具调用参数、工具结果、后台认知及压缩内容不受字符裁剪。

终端示意：

```text
────────────────────────────────────────────────
[你]
  > 我去改改你的语气。
  发送时间：2026-10-21 01:42:05

────────────────────────────────────────────────
[小温暖]  2026-10-21 01:42:11
  好，我在这儿等你。刚才那些长篇大论也一起收好了，免得你回来，又被我念叨一通。唔，我还是有点自知之明的。
```

时间按Asia/Shanghai显示。用户时间在回车接收后显示；助手时间来自持久化回复记录。上下文仍携带每条消息的时间用于理解“刚才、明天”等相对时间，但它是内部元数据，不能由模型自行填写在正文。程序移除模型复述的前导ISO时间标签，保留正文中真正引用的时间。旧历史消息原样保留。

配置在 `[context]` 下：

```toml
reply_min_chars = 40
reply_max_chars = 80
reply_max_tokens = 512
```

`reply_max_chars = 0` 可关闭字数限制；这不是当前默认。模型输出token上限与字数上限不同。聊天保留模型实际用量计费，字数裁剪不退还已生成token，也不增加API改写调用。已呈现正文、持久化助手原话和完整协议检查点保持一致。

现有库已从persona@4版本化更新为persona@5，变更前先备份。原话、人格旧版本、继承记忆边界和其余条目保持。模板只负责首次初始化，现有库不能靠重新init或手改记录升级。

在旧窗口输入 `/quit`，然后重新双击 `启动小温暖.cmd`。30轮完整诊断、50轮记忆/情绪整理、150轮深度整理、300轮人格审阅、50M每日预算及650k压缩阈值不变。

验证范围是离线代码、协议、排版、持久化与档案完整性；未增加真实API调用，真实语气是否自然仍以实际聊天反馈为准。
