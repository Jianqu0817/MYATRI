## 环境与启动

在 D:/DS_workspace/MYATRI，Windows Python3.12（实测3.12.7），uv。普通运行 `uv sync --frozen`；神经模型 `uv sync --frozen --extra neural`。锁文件是实际解析结果。依赖版本见 reports/environment_smoke.json。无须安装任何参考项目。

所有全局选项在子命令前：`myatri --root <目录> --agent atri --user local --config config/defaults.toml <命令>`。下文myatri可替换为 `.venv/Scripts/myatri.exe`；不激活环境也可用绝对路径。

## 向量与检查

默认TF-IDF是词面向量，空间随语料版本变化，自包含恢复。`memory rebuild-index --space tfidf`重建。可选BGE：显式 `models download --path var/models/bge-small-zh-v1.5`，然后 `memory rebuild-index --space bge --model-path <模型目录>`；选择保存到运行库，重启使用同一模型；模型文件不自动下载。跨机器恢复BGE需重新指向本地模型目录（manifest校验），或显式切回TF-IDF。模型hash见 reports/model_manifest.json。`memory rollback-index <generation>`回退旧generation，索引滞后会注明并用原文/全文回退。

`memory list`、`memory inspect <id或id@revision>`显示对象和完整来源链；`recall <问题> --explain`返回版本、理由、路径、反例和局限，可加 `--date-from 2026-09-01 --date-to 2026-09-30 --person 同伴 --kind event`。未知发生日期不填为创建日；人格变化可 `recall 为什么更愿意表达期待 --kind persona_change`。

`graph inspect`含真实算法参数/seed/群落/谱系/主题；`graph inspect --theme <id>`看代表/差异/反例。`persona show`、`persona diff 1 2`与 `persona restore 1`；恢复创建新版本和变化记录，不删除旧人格。反思 `reflect --scope all`或指定主题ID；离线默认defer是已记录决策，不是模拟人格成功。

## 临时状态与压缩

`state list --status open`；`state inspect <id> --activation-trace`；`state dismiss <id> --reason <理由>`保存撤回新版本。近期感受是同一TemporaryEntry视图。状态可open/paused/settled/discarded/consolidated；foreground仅本轮注意，不改生命周期。撤回后旧摘要失效，历史仍可用 `recall <问题> --historical`查到。

只有持久assistant消息才支持已表达/尝试，无反馈保持unknown；迟到反馈可追加原尝试但不能重写原动作或复活撤回状态。对话中的自然表达不是主动向外发消息。临时状态只能经真正已提交PersonaChange原子巩固。人格修订需版本/hash、独立事件根、反例检索记录、绑定提案的A7审阅与局部patch，语义证据不足可以不修改。

`compact --preserve <raw消息ID...>`与自动压缩走同一路径，从原文重建而非递归缩写旧摘要。保留约定/指定引文及source pointers；大内容以read_record恢复，不能无限放入上下文。预算估计为保守UTF-8字节上界，完整计算tools/protocol/output预留；固定内容仍超限会明确报错，不裁掉规则或切断工具协议。`context`解释当前组装。

`protocol inspect <原始用户消息ID>`检查工具完整往返及供应商必要协议字段；它位于runtime.sqlite3，不属于可检索经历或临时念头，不能拿协议推理当外部证据。完整工具边界会持久保存以支持重启续接。运行库备份视为敏感用户数据，不公开分享。

## 存储、导入与故障恢复

运行目录含 domains/<隔离hash>/records 与 commits：不可变JSON+校验manifest是权威。SQLite投影/FTS与indexes为派生；runtime.sqlite3保存队列、用量、日程、完整工具协议，不能只凭经历档案恢复任意进行中的调用。

不要手改已发布records/manifest。`memory import <Record.json>`只接受显式human_import，revision必须紧接且标supersedes_revision、来源存在；事件/消息不可改，只追加解释。人格版本/变化不能独立导入绕过原子patch，临时状态导入不能直接consolidated。当前不提供普通全文覆盖人格接口。

`doctor`校验档案hash/来源及巩固关系。篡改会报告并拒绝恢复，不会悄悄覆盖。可删投影后启动重建；索引损坏时保留档案，移走损坏indexes后执行memory rebuild-index，不删除records/commits。若启动已报索引hash不符，先停止所有worker，保留该目录用于诊断，再显式移动indexes到新备份位置。

`backup --output <运行目录外的新zip>`在单写锁下复制权威档案/索引，并使用SQLite在线backup保存队列；投影重建。`restore --input <zip> --target <不存在的新目录>`检验成员路径/符号链接/档案完整性，不覆盖旧目录。恢复后可重复执行doctor/worker --once；已有生成结果先持久化再提交，重启无需重新生成；租约到期重新领取，语义CAS冲突保留结果并报错，不盲目覆盖。
