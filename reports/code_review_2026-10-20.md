档案权威与可重建索引分离、事件与解释分开、外部证据根去重、A7 绑定具体 patch、CAS 与原子人格提交，都是应保留的设计。本轮没有找到新的常规 A6/A7 证据根绕过；索引失败也不代表用户原文丢失。

## 设计与评估意见

1. **先证明能持续运行，再加新记忆对象。** 下一轮验收应覆盖多次自动压缩、跨压缩的新约定、状态更新后全索引重建、重启后继续对话，以及不断加入新材料时 A1/A5 的处理进度。当前一次压缩/小样本闭环测试遗漏了这些关键情境。
2. **优先按水位和来源分配工作。** 持久化存储可以增长，但每次模型输入和前台等待应有界。不能用不断提高 token 上限掩盖全量历史输入，也不能让每条新消息触发完整全库处理。
3. **把语义归因和机械完整性分开。** 模型负责建议“这次表达对应哪个意图、哪些后续是反馈”；程序核查确切原文、事件范围、版本和未知结果。保留不尝试、不改变、defer 和放弃的合法结果。
4. **新实体/技能设计维持待实现标记。** 当前 participants 字符串不等于稳定实体身份，主题不等于技能掌握，512-token BGE 截断也不等于全文语义覆盖。DMI 实施先同步公共契约及任务清单，不需要为这些目标更换整套架构。
5. **按真实任务比较检索收益。** 现有 evaluation 仍是少量关键词合成样本，且图/主题/多视角已有负结果；本轮没有重新测语义质量。后续增加同名人物、否定、更正、旧事导入、跨多次压缩约定和角色连续性的独立样本，记录来源正确性、反例、延迟与成本，不能只看 Recall@5。
6. **集中生命周期与保护策略。** 是否允许退休状态经过中间态重新开放、哪些身份条目允许自动改、关系 valid_from/valid_to/status 如何影响“当前”查询，需要明确后由同一业务边界检查。当前这些并非都有完整程序约束。失败任务 retry 入口、后台异常监督亦是后续运维建议，未当作本轮已复现的独立生产缺陷。

建议执行顺序：CTX-01 / R-MEM-03 / M01 / A04 → A06 的有界材料规划与 M02 发布检查 → R01 与排程/预算 → A05 日常归因 → 实体/技能与独立长期评估。修复后把确认缺陷纳入默认正常回归；原 strict xfail 应在修复时移除并改为正常 test_ 收集。
