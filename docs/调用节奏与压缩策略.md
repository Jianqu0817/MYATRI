# 调用节奏与压缩策略

0.1.5补记（2026-10-21）：最新普通运行频率为诊断10轮、记忆/情绪/状态30轮、反思约90轮、人格审阅约180轮。原话仍即时保存，650k软阈值和压缩前依赖顺序保留；积压的深度审阅在压缩前补跑。消息发送时间、缓存与增量投影见[运行开销优化](运行开销优化_0.1.5.md)。下文保留0.1.4历史设计。

2026-10-21，MYATRI 0.1.4。

## 为什么调整

原实现对每条用户消息抽取经历，并从索引更新启动关联、主题、反思、临时状态、人格审阅等后续任务；前台还可能单独调用模型选择状态。实际用户库已观察到后台调用远多于聊天请求。原会话上限是保守的16k UTF-8字节估计，容易在短对话后开始分块压缩。

用户要求减少额外调用，约650k上下文再压缩，压缩前完成依赖上下文的整理。20轮是工程初值，可配置，不是心理变化或证据充分的标准。

## 现在的运行规则

- 原始用户消息在模型等待前保存，助手回复成功后保存；不等20轮才写原话。
- 一轮指一条用户输入及其成功返回的助手回复。失败的输入仍保存，不增加完成轮数。后台批次以不可变原话ref为范围，包含该范围内尚未整理的失败输入。
- 每20个完成轮次安排一个维护批次。A1把多条短消息合并进有界请求，并验证每条事件的message_ref和逐字quote。长消息保留窗口、重叠去重和可恢复checkpoint。
- 情绪以最多6个独立事件合并评价，按原接收时刻回放。它是延后评价，不冒称事件发生当时已产生的体验。每个事件都要给出propose/defer/reject，情绪不会直接改人格。
- 反思、临时状态、归因、关联/主题和人格审阅按批次执行。有材料才调用，可明确defer。主题摘要每批最多两个。计数只触发审查，不充当成长证据。
- 前台已有状态改用本地相关性选择；不再为每次状态激活额外调用LLM。即时情绪/心境的时间回归仍是本地数值计算。
- 新策略不再额外按空闲、夜间、3小时间隔启动认知任务。显式reflect/emotion命令仍可运行。

## 压缩顺序

自动压缩或显式 `/compact`/`compact --mode live` 走同一异步入口：先整理尚未覆盖的用户原话，再评价情绪、反思/调整临时状态及必要审阅、更新索引，然后才生成会话摘要。

维护游标仅在依赖完成或有明确defer记录后前进。每阶段保存进度，重启复用已完成工作。依赖超时、预算不足或来源校验失败时不先压缩；原话保留。正在运行的批次和前台压缩通过同进程异步锁协调，重复范围会检查覆盖游标。

每阶段请求有材料预算；摘要不会无限包含全文。压缩从原话提取逐字来源，不递归缩写旧摘要。最近6条原话及显式preserve仍保留；仅有少量最新/固定内容且无法减小时不反复做无进展压缩。原话不会因此删除。

## 配置和计数

一键启动使用 `config/live.local.toml`，公共模板是 `config/live.example.toml`：

```toml
[context]
limit = 1000000
compact_at = 650000
output_reserve = 4096
safety = 4096
compaction_chunk_bytes = 200000
compaction_max_chunks = 16
llm_compaction = true
llm_activation = false

[cognition]
maintenance_turns = 20
```

`limit`是单次上下文硬预算，`compact_at`是开始压缩的软阈值，`budget.daily_tokens`是当天所有付费请求的共享额度，三者分开。默认配置文件也已同步；不传配置的旧程序接口保留legacy行为，便于兼容现有离线脚本/测试。

官方当前声明deepseek-flash支持1M上下文：[DeepSeek模型文档](https://api-docs.deepseek.com/quick_start/pricing/)。650k是用户选择的保守触发点，不是测得的最佳阈值。

程序没有引入精确tokenizer。每次有API实际prompt_tokens后保存用量锚点和消息块哈希；下一请求对新增/改变块按UTF-8字节上界增加估计，不冒险扣减已移除块。新摘要组装后重新用保守估计，后续真实usage再次校准。首次请求或没有usage时使用字节上界。因此650k是估计阈值，不能声称精确达到650000模型token才触发；不会把650k字符当650k token。

## 迁移、验证和限制

重启后新策略接管旧的逐消息认知任务，将其标为cancelled并注明由批处理接续。原话和已有模型结果不删除；不是把未完成任务伪装成已整理。旧的活跃worker应退出后再使用新启动器。

阶段checkpoint与单写提交保留，但当前维护协调锁只覆盖同一进程；正常使用只开一个聊天实例，不应额外另开付费worker与它同时做维护。65万真实token长对话和新批量prompt尚未做真实API验证。本轮只做离线工程测试，不启动用户聊天、不调用模型服务。

此前检查发现的验证码不再召回/到期撤回、所有自然问法的稳定检索等问题仍开放。降频改善运行节奏，不意味着长期记忆质量或遗忘语义已经全部解决。每20轮还可能产生数次有界请求，不是所有语义工作强行塞进一次调用。
