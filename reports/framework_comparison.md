# MYATRI 与持久化Agent框架的定位比较

2026-10-20。对照当前本地源码/审查记录，以及本次查阅的官方文档；没有安装或同条件运行这些外部框架，也没有追加模型API调用。工程定位判断与实测性能分开。

## 不同层次的产品

|对象|官方能力重点|MYATRI的取向差异|
|---|---|---|
|LangGraph|checkpointer保存线程状态，store保存跨线程数据；恢复、人工介入等属于运行框架能力|MYATRI自行实现轻量队列/提交，更具体地定义事件、临时状态及人格演化规则|
|Letta|有状态Agent；当前SDK用版本化记忆仓库/MemFS，system记忆进上下文，其他内容按需读取；Dreaming后台整理|两者重叠明显，持久角色/后台整理并非MYATRI独有；我们的特定重心是人格修改的外部事件根、反例、局部patch与审阅绑定|
|Mem0|面向Agent应用的记忆层，用户/会话/Agent信息与检索、个性化|我们增加角色自身临时意图/感受、实践反馈接口和局部人格协议；Mem0可作为记忆组件，不能笼统说其只会存事实|
|Graphiti/Zep|Graphiti开放时序知识图谱，实体/关系/episode来源与混合检索；Zep提供托管上下文设施|我们主要用事件相似图/Leiden主题组织，并将其接到角色状态与人格；不等同成熟双时间事实图|

来源：[LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)、[Letta当前SDK Memory](https://docs.letta.com/agent-sdk/memory)、[Mem0官方仓库](https://github.com/mem0ai/mem0)、[Graphiti官方仓库](https://github.com/getzep/graphiti)。

特别注意版本：Letta当前SDK与V1 memory blocks概念/接口有变化，不能只据旧文档评价当前产品；Mem0当前README介绍ADD-only提取及混合检索，且明确托管平台含私有优化、与开源SDK不同，不能把它描述为只会覆盖旧记忆。此处不转述厂商跑分为独立证据。

## 当前可主张的适配优势

1. 原文span、事件、解释/反思、状态、人格变化分轨；自我反思及重复提及不增加独立外部事件根。适合检验角色是否拿自身猜测反复强化。
2. 统一临时状态生命周期，支持共存矛盾、暂缓/放弃；语义激活只决定本轮注意，不是行动或人格巩固。最新API路径已实际短测。
3. 局部人格patch绑定当前版本、旧hash、外部根、反例检索和确切A7审阅；人格/变化/巩固状态原子提交，有恢复与来源回查。这是具体业务约束的组合，其他框架也可实现。
4. 对单机单角色实验，JSON权威档案+SQLite/可重建索引可检查，便于替换模型/检索后端。存储层有实际Windows崩溃/CAS测试；不意味着索引并发已经全部正确。

版本化、向量检索、来源追踪、图、后台反思、LLM摘要都不是独创证明，也未证实性能领先。MYATRI更适合称为面向可追溯角色演化的定制原型，而非通用框架的全面替代。

## 必须同时说明的短板

- M01旧快照用未来关系、M02并发索引发布倒退仍未修；A05普通聊天尚未自动归因实际行动/反馈，完整日常闭环未验收。
- 全量档案/索引/图重建、后台选材预算、部分调度和跨实例预算仍有限制；单用户CLI没有完整服务平台/多会话管理/权限UI。
- 人格身份不可变条目尚无硬锁；A6/A7真实人格判断及长期角色连续性未验证。
- 最新116项回归和2次新功能live只证明相应边界/短协议；既有36个关键词合成会话中，图/主题、多视角未稳定改善排序。

本地证据：reports/llm_context_upgrade.md、reports/component_review.md、reports/evaluation.md、reports/audit_memory_2026-10-20.json；memory子Agent独立核对本地成熟度，未改生产或调用API。

## 下一步判断标准

先修一致性和日常行动反馈集成，再用相同模型、历史材料与总费用预算做对照。分别评价事实回忆/原话保真、更新与撤回、无证据时弃答、人格局部性/长期连续性、来源回查，以及延迟/总调用成本。我们当前较明确的是产品目标与约束；效果优势须由这些对照证明。未来可替换运行层或图层，无需把领域协议与某个框架绑定。
