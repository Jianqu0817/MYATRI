## 目标和边界

让角色在经历后保持连续的即时情绪与较慢的心境，并能说明变化来自什么经历。事件的意义由现有LLM网关评价；程序承担时间演化、来源检查、幂等和预算。情绪余波复用TemporaryEntry，不另建不可追踪的“暗流池”。情绪不直接修改人格，不把用户未联系解释为冷落，不实现疲劳导致事实混乱、强制爆发或自动外发。

## 工程方案

- `_vendor/emotional_memory.py`：带来源标记的小型纯函数；PAD、回归、EMA与距离。完整MIT许可和锁定来源加入LICENSES/upstream。
- `contracts/emotion.py`：有界PAD、配置、情绪评价与人工撤回契约。情绪评价是派生记录，不是新外部事件。
- `cognition/emotion.py`与版本prompt：读取有界事件、初始人格和上下文，LLM可propose/defer/reject；逐字来源校验，不把用户情绪直接当角色情绪。
- `persona/emotion.py`：按不可变评价记录的时间顺序回放即时情绪与心境；只读计算经过时间后的回归，不按定时器产生新证据或API请求。
- `Application`和队列：新事件入库后安排幂等情绪任务，结果经统一提交器发布；重启可补排。模型失败保存为任务失败，不伪造语义评价。
- 对话上下文：注入有界状态说明及来源；属于暂定数据，不覆盖人格/事实/权限。诊断可见选用来源和计算时点。
- CLI：`emotion show/history/appraise/dismiss`，显式检查、对一个事件安排评价或撤回误判。
- 可选心境排序：只在已检索候选内做有限调整，保留基础头部与反证；默认关闭，等待实际语义评估，不影响人格审阅的证据搜索。

## 状态与来源

原始消息 → 不可变Event → LLM情绪评价（含意义、PAD目标、置信、逐字依据） → 确定性状态投影 → 对话。

每个Event最多一条v1情绪评价，重复处理/回忆/反思不增加冲击。即时情绪和心境使用不同恢复时间。时间锚点是原始消息被系统接收的时刻，不是转述中事件发生的年代；历史补处理按原接收时间回放。默认参数是可调工程值，未经心理学标定。新配置会改变派生投影，原评价不改；诊断输出参数指纹。

具体计算：每轴先按`baseline + (current - baseline) * 2^(-elapsed / effective_half_life)`回归；即时情绪再按`emotion_alpha * confidence`向本事件target插值；心境按`mood_alpha * confidence * (1-inertia)`缓慢更新，心境effective_half_life为配置值乘`(1+2*inertia)`。默认即时半衰期1800秒，心境基础半衰期21600秒、inertia=0.5，因此默认心境实际半衰期为12小时。这些只是可调整的工程参数。

旧情绪评价不可覆盖。人工撤回写入独立emotion_retraction，并在同一原子提案中discard对应仍open/paused的余波；旧快照仍读得到原状态，不悄悄回滚已独立审阅的人格修改。v1暂不支持撤回后对同一事件重新评价；需要新解释时以新的有来源经历进入流程，未来另设计显式评价修订协议。

后台评价不阻塞首轮回答，通常从后续轮次读取到连续状态；“即时情绪”指较快的状态时间尺度，并非额外同步前台请求。模型首轮仍可根据原始对话自然理解情境。旧库事件不自动批量回填，只有新Event发布后自动排队，旧事件用显式appraise。任务保存结果后重启可直接提交，不再次调用模型。没有新增常驻计时进程。

回放的顺序确定性只指给定已提交评价的数值演化。LLM评价可能因当时可见上下文、并发任务或模型采样不同；run记录既有情绪投影与材料快照，不能宣称模型语义结果调度无关。

未解决关切可生成一个带原事件与评价来源的emotional_echo，由现有临时状态生命周期处理。数值恢复不自动结清关切。人格仍走原有A6/A7与统一提交，不从PAD数值自动推导。

## 验收计划

- 上游公式等价、有限数与边界检查、时间分段一致、倒退时钟拒绝。
- 原始来源/角色/快照/跨用户隔离、重复根去重、重启回放与乱序任务一致。
- 语义评价defer、伪造quote/外部ref拒绝、材料不足明确延期。
- 前台上下文/预算/临时余波/可选排序接线；反证不被情绪清除。
- 普通离线回归与发行包许可检查；不读取真实密钥、不新增付费调用。

## 使用与接续

在项目目录运行，以下show/history/dismiss均离线；`--root`应指向要检查的角色库，新测试请使用独立目录：

```powershell
.venv/Scripts/python.exe -m myatri.interfaces.cli --root var/emotion-demo init
.venv/Scripts/python.exe -m myatri.interfaces.cli --root var/emotion-demo emotion show
.venv/Scripts/python.exe -m myatri.interfaces.cli --root var/emotion-demo emotion history
# 对已存在的event_id@1评价；默认offline会明确defer，不伪造模型理解
.venv/Scripts/python.exe -m myatri.interfaces.cli --root var/emotion-demo emotion appraise event_id@1
# 对已存在的评价做人工撤回
.venv/Scripts/python.exe -m myatri.interfaces.cli --root var/emotion-demo emotion dismiss emotion_id@1 --reason '该评价误解上下文'
```

`emotion show --at <带时区ISO时间> --snapshot <commit_id>`可复验指定材料快照的时间投影。`--at`只指定数值计算时点；要恢复旧时可见的评价/撤回/余波版本，必须同时选择旧snapshot。history保留原评价；撤回记录可用memory list/inspect按种类查看。

`emotion appraise`沿用现有drain行为，会处理当前库的其他到期队列任务，不能把它当成只执行一次模型调用。真实模式须另用现有显式live配置；该阶段与其他后台任务共享日token预算。enabled=false关闭投影和新增评价，llm_appraisal=false仅停止新增语义请求、已有投影仍可读取。读取/时间回归/撤回不调用模型。

## 尚未验证或尚未实现

- 新emotion prompt的真实DeepSeek语义判断、长时间角色自然性、置信度校准尚未验证；离线fixture、数学等价和工程测试不替代这些结果。
- 可选心境排序只重排已召回候选中已标注的部分，固定前4项与所有反证，无删除/新建候选；默认关闭，不宣称改善召回效果，不作用于人格证据搜索。
- 状态从全部可见评价重放，时间/内存开销随历史增长；没有增量检查点或大规模性能保证。
- 没有疲劳降智、强制爆发、沉默扣信任、自动改人格或联系人外发；也未引入OCEAN人格数值替代已有角色卡。
- 人工撤回只影响该情绪投影及其直接未退休余波，不递归修改后续经历、已独立形成的解释或人格；v1没有自动重新评价整条后续链。
